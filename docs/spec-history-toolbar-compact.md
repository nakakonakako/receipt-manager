# Receipt 履歴・管理画面：上部UIコンパクト化 B案 仕様（実装用ドラフト）

- 作成日: 2026-11-10
- 状態: **B案を試作するための仕様。実装・ブラウザー検証は未完了**
- 対象repo: `nakakonakako/receipt-manager`
- 想定配置先: `docs/spec-history-toolbar-compact.md`
- 対象: `frontend/src/features/history/components/HistoryPage.tsx` の履歴一覧上部の操作領域
- 関連: `frontend/src/features/history/hooks/useHistory.ts`、`frontend/src/components/MainLayout.tsx`、`docs/spec-main-navigation.md`
- 関係: 共通設計原則とは別タスク。この改修で設計原則の導入や全面統一を実施しない

## 1. 課題と目的

現状の履歴画面には、(1)「この月だけ検索／全期間検索」、(2) 検索入力と新旧並び順、(3)「レシート／キャッシュレス」、(4) 月選択・移動と合計表示、の4グループが縦積みで存在する。PCの一覧開始位置が下がり、初期画面に表示できる取引履歴の数を減らしている。

**目的**: 操作の意味と既存機能を維持しながら、上部領域をPCで原則2段に整理し、取引履歴をより上から表示する。

これは**UI配置・余白・大きさの改修**であり、検索ロジックや集計仕様を再定義する改修ではない。

## 2. 今回採用する方向（B案）

- **採用**: 既存の履歴エリアの上部にコンパクトなツールバーを設置する。
- **不採用**: 右側余白に常設の操作パネルを移設するA案。
- **不採用**: 右側に取引詳細を開くC案、独立したフィルタードロワー、stickyツールバー等の新機能。
- アプリ全体のPC左サイドバー・アカウント配置はそのまま保持し、履歴画面の内側だけを変更する。

### PC画面の2段構成イメージ（機能を示す模式図）

```text
┌───────────────────────────────────────────────────────────────────┐
│ [レシート | キャッシュレス]   [‹ 2026年5月 ▾ ›]  表示中の合計 ¥10,709 │
│ [検索: 店名や商品名で検索........................] [この月 ▼] [新しい順] │
├───────────────────────────────────────────────────────────────────┤
│ 2026-05-31   店名...................................  ¥464  編集 削除│
│ 2026-05-31   店名...................................  ¥466  編集 削除│
│ ...                                                               │
└───────────────────────────────────────────────────────────────────┘
```

- **1段目: 何を表示しているか** — レシート／キャッシュレス切替、月送り・月選択、条件に対応する合計。
- **2段目: どう探し・並べるか** — 検索欄、現在月／全期間切替、並び順。
- 各要素の意味上の関連を優先し、単に要素を縮小・詰め込みしない。
- 狭い画面では必要な行に自然に折り返す。スマホまで2段固定にしない。

## 3. 各操作の仕様（現状維持）

| 項目 | 表示方法の案 | 維持すべき既存動作 |
| --- | --- | --- |
| 表示対象 | 1段目左のセグメント切替 | `activeTab: receipts/csv`。選択色を維持し、各タブの月を独立して記憶 |
| 月送り・月選択 | 1段目中央の小型コントロール | 現在月モードのみ表示。前後移動の無効条件、月ドロップダウンの選択・閉じる挙動を維持 |
| 合計 | 1段目右に短いラベル付きで表示 | 現状と同様に検索後の表示結果を合計。データ種別に応じた数値・色を維持 |
| テキスト検索 | 2段目の入力欄。入力幅を最優先 | Receiptは店舗名・商品名・検索タグ、CSVは店舗名に対する既存の照合を維持 |
| 検索範囲 | 検索欄近くの明示的な切替 | `searchScope: current/all` を変更するだけ。全期間の既存取得動作を維持 |
| 並び順 | 2段目右、状態が分かるボタン | 新しい順／古い順のトグル動作と表示ラベルを維持 |

**重要な境界**:

- 現状の `searchScope='all'` では月選択領域ごと非表示になり、合計表示も月選択領域内にあるため非表示になる。今回も**全期間時に新しい合計表示を追加しない**。全期間での合計表示は別の仕様判断とする。
- `searchScope` と `searchQuery` と `sortOrder` は表示対象を切り替えても共有される。新たにタブ別状態へ変更しない。
- 月の取得、遅延ロード、レシート編集・削除、CSV編集・削除、検索対象、合計の計算は変更しない。
- 「この月だけ検索／全期間検索」の文言を短くするときは、現行の `searchScope` が検索と表示一覧の両方に効くことを考慮する。例えば「この月」「全期間」だけでは曖昧になるなら `aria-label`、ツールチップ、補助ラベルで明確化する。
- 現在月モードでデータが0件でも月切替の挙動を変えない。全期間モードでも表示対象が分かるよう検索範囲コントロールを残す。

## 4. レスポンシブ配置

| ビューポート | 方向 | 注意事項 |
| --- | --- | --- |
| 1280px以上のPC | 1段目に表示対象・月・合計、2段目に検索・範囲・並び | メインの現在の最大幅を維持。2段目の検索欄を極端に狭くしない |
| 640〜1279px | 利用可能なコンテンツ幅に応じ2〜3段へ折り返す | アプリ本体の上部ナビゲーションと干渉しない |
| 639px以下 | 読みやすい順序で縦・折返し配置 | タップ領域を守り、左右へのはみ出し・日付/金額の欠落を防ぐ |

- 最初の実装案としてPCの主要操作はおおむね高さ40〜44px、行間8〜12pxを目安にし、現行のCSS・アクセシビリティ基準と比較して決める。これは確定の寸法指定ではない。
- 月選択ドロップダウンは周囲のカード・スクロール領域で欠けず、フォーカスと閉じる操作が働くこと。
- 複数の縦スクロールを増やしたり、横ずれ防止の既存CSSを変更したりしない。

## 5. 非対象（今回変更しない）

- 新しいフィルター、検索演算子、日付範囲指定、検索対象の拡張
- API、DB、取得頻度・キャッシュ、集計・金額計算、ソート処理の変更
- 履歴カードのデザイン、編集・削除モーダル、一覧の行密度・件数表示
- 新たな右サイドパネル、グラフ、stickyツールバー、詳細ビュー
- アプリ全体の左サイドバー／ヘッダー変更、他タブのデザイン変更
- Memo側の実装、共通デザインシステムの作成、共通UIライブラリの導入

## 6. 受け入れ条件と測定項目

### 振る舞いの維持

- [ ] レシート／キャッシュレス切替、月移動・月選択、検索範囲、検索語、新旧順が変更前と同じ結果を返す。
- [ ] 各種組み合わせ（種別×この月/全期間×検索語×並び順）で画面の表示内容が一致する。
- [ ] 金額表示は現行の条件・計算結果と同じで、全期間モードには今回新たな合計を追加しない。
- [ ] 読み込み、検索0件、データ0件、月未選択、月ドロップダウンの状態が破綻しない。
- [ ] レシートの編集／削除、CSVの編集／削除、レシート明細の展開・折りたたみへ回帰がない。

### UIの評価

- [ ] PC（1440×900、1280×900を目安）で操作領域の高さと**最初の履歴カード上端のY座標**を変更前後で計測する。削減量を報告し、数値は実測に基づいて採否判断する。
- [ ] 1024px、768px、390px、320px程度で横オーバーフロー・文字切れ・操作の重なりを確認する。
- [ ] 主要操作のキーボード移動順とフォーカスの可視性を確認する。
- [ ] 小さなアイコンだけの操作には分かる名称を用意する。主要なスマホ操作は44px程度を設計目標とする。
- [ ] 月ドロップダウンが正しく前面に表示され、外側クリック／選択後に閉じる。
- [ ] 画面全体・履歴領域のスクロール、スクロールバー幅、配置の安定性を維持する。
- [ ] 同じデータ条件の変更前後スクリーンショットとDOMの計測結果を報告する。

### 開発プロセス

- [ ] 最新 `origin/main` を起点に専用worktreeを作成し、既存worktreeを壊さない。
- [ ] `AGENTS.md` のCodex→Cursor委譲と公式Playwright MCPの経路に従って検証する。
- [ ] 関連するコンポーネントの回帰テストを追加／更新し、`npm run check` と `git diff --check` を実行する。

## 7. 実装に関する判断の余地

- JSXの要素グループ分割・共通化は、今回の上部領域を分かりやすくするために必要な範囲に限定する。大規模なコンポーネント階層変更は行わない。
- 2段配置が操作ラベルの視認性や入力幅を損なう場合、**一部折返しを優先**する。2段達成のために操作を隠す、タップ領域を縮小する、独自の複雑なメニューを追加することは避ける。
- アプリ横断のUI原則やトークン導入は、別の文書・別のPRで検討する。
