# 予定: 履歴の分類フィルタ（大分類・サブカテゴリ）

ステータス: **未着手（構想のみ）**  
最終更新: 2026-08-25  
対象: 機能 A / 履歴・管理ページ

## 1. 背景

履歴のテキスト検索は現状、次だけを対象にしている。

- 店舗名
- 商品名
- `search_tags`（言い換え・類義のキーワード配列）

`main_category` / `sub_category` は検索対象外。  
これらをテキスト欄に足す案もあるが、**キーワード検索と分類フィルタは役割が違う**ため、同じ欄に混ぜない方針とする。

## 2. フィールドの役割整理（前提）

| フィールド | 個数 | 役割 |
|------------|------|------|
| `main_category` | 1（固定8択） | 家計の大分類。統計円グラフにも使用 |
| `sub_category` | 1（自由入力） | 分類の棚（野菜・肉類・調味料など） |
| `search_tags` | 複数 | 名前が違っても探せる言い換え・用途語 |

サブとタグは語が被ることがある（例: 両方に「中華」）。  
それでも「棚で絞る」と「言い換えで探す」は別操作に保つ。

## 3. 予定する UX

テキスト検索欄は現状のまま（店舗・商品名・タグ）。

分類は **別 UI の候補選択で抽出**する。

1. **大分類** … 固定リストからチップ / ドロップダウンで選択
2. **サブカテゴリ** … いまのデータに存在する値だけを候補化し、その中から選ぶ  
   （マスタを別管理しない。自由入力の全文検索にしない）

操作イメージ: 「食費 → 肉類」のように段階的に絞る。

テキスト欄に大分類名・サブ名を直接打ち込んでヒットさせる方式は、採用しない（優先度低・非推奨）。

## 4. やらないこと（この構想の範囲外）

- 凝ったファセット UI の初手実装
- サブカテゴリの共通マスタ管理
- サブカテゴリ単位の統計ダッシュボード拡張
- B（厳密比較）の手動フォルダとの統合

## 5. 実装タイミングの目安

- A の本流は既に使える状態なので、**B 着手をブロックしない**
- 「食費だけ見たい」などが実際に不便になってから、まず **大分類チップ** だけ入れる
- サブ候補リストはその次
